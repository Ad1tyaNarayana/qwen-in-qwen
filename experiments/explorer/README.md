# Qwenputer Explorer

An offline atlas of the unified W=4 CPU compiled into the Qwen3.5 architecture.
It connects the actual compiler graph, generated CPU trace tokens, ELF symbols,
and decoded neural recurrent state. All work is under this directory and is
uncommitted. No upstream files, packages or other experiments were changed.

## Launch

From the repository root, run:

```sh
python3 experiments/explorer/server.py
```

Open <http://127.0.0.1:8792>. The server binds to localhost. It needs only the
Python standard library. The checked-in-ready data bundles require no model,
GPU, npm build, CDN, internet connection or package installation. A browser
with ES modules and `DecompressionStream` is required. Chrome was verified.

Drag the network to orbit. Scroll to zoom. Click a point or use the searchable,
paginated unit list. Select a layer or role to reduce overlap. The scale slider
and L0 through L4 buttons switch semantic levels. Breadcrumbs return to earlier
levels. The bottom timeline remains shared across the views. Teal ticks mark
available neural snapshots; the gold line marks the selected generated prefix.
Playback advances recorded tokens, not wall time.

The point selector offers active MLP units and heads, residual slots, and the
complete zero-padded stock capacity. The last mode has roughly 600,000 points
and is more expensive to orbit. The active map is the default. No points are
randomly sampled or given invented activity values.

## What the levels show

| Level | Data and interaction |
| --- | --- |
| L0 Network | 64 linear-attention layers, 627 active key heads, 1,247 logical value heads, 68,923 IR FFN terms, stock exit-clear units, and the appended zero full-attention layer. One point per unit. Hover shows its name, role and emitted weight statistics. The residual mode shows all 2,304 hidden coordinates at every layer, including ballast, reserved tau, mapped IR slots and unused padding. |
| L1 Layer/unit | Exact FFN coefficient and input/gate expressions; per-layer head tables; head output routing and weight statistics; raw S heatmaps where captured; register, RAM and DROM axes; and every physical residual slot's logical owners, lifetimes, pinning and clear handovers. |
| L2 CPU | PC and instruction decoded from generated tokens and static ELF code, token/value records, NDOT activity, address map, all three recurrent register copies, and byte-addressable RAM when a neural sample exists. Click an object in RAM to follow its ELF symbol. |
| L3 Program | Real ELF functions and object symbols, static RV32IM/NDOT disassembly, hot-function totals and a clickable function timeline. Counts are token positions, not retired instructions or GPU times. A dynamic call stack is not reconstructed. |
| L4 Application | Actual generated BYTE output and inner token IDs, five inner LLM layers, activations, logits and KV cache decoded from neural RAM at the retained final sample. KV slices use actual `[layer][position][dimension]` addresses. Showcase manifests render published Life, MNIST and tic-tac-toe outputs with their original provenance. SHA-256 outputs are shown as digests. Local manifest decoders can render Doom strips and guest RAM arrays. |

The inner model has dimension 64, five layers and eight query heads. Its
geometry, KV precision and context come from this ELF's `pack.json`. Activations
are shared C scratch arrays, so selecting an inner layer does not invent a past
activation history. KV cache has separate storage for each layer and position.
The memory inspector uses ELF symbol sizes, not a guessed C layout. `att` is Q15;
ordinary activation/logit buffers are Q12, KV uses the configured fractional
bits, and `quant` has a dynamic scale.

## Included real recordings

`data/recordings/index.json` contains three windows imported on the Mac from the
accepted autonomous fused 38-position stories260K run:

* `boot` has 8,192 actual generated tokens.
* `stories260k-position-0` has 1,041,913 actual generated tokens. It includes one
  complete inner forward position, diagnostic output and its decoded text.
* `stories260k-final` has the last 4,096 generated tokens, the preceding actual
  BYTE output as small context, and one exact neural snapshot at generated
  prefix 53,296,563. That snapshot includes all 65,536 RAM bytes, 96 register
  values, PC anchor/count, and raw slices of `pc`, `count`, `regs.rs1`, `ram3`
  and `drom0`.

The whole original generated trace was compared against the retained independent
trace before extraction. The checkpoint SHA256 is
`386909d5ab9d8093202c68f29971aa7fb76285fbe69c4358b2a91fe0296ba228`.
The original 203 MiB trace and 79 MiB checkpoint stay in `.cache/`; they are not
part of the app. There are no Doom pixels or WAD-derived artifacts here.

The static graph and layer details total about 1.4 MiB compressed. The recording
bundles total about 1.3 MiB, including the full-position trace. Eight PNG
screenshots total about 2.2 MiB. Filesystem block sizes differ from byte sizes.
`data-sizes.json` records exact file bytes.

## Provenance rules

* **Compiled IR** means structural information from `constructor.build(4)`, its
  freshly regenerated reuse ledger and the pinned stock emitter. Role colors
  group compiler names by an explicit prefix table. Unclassified symbols retain
  their exact names and say so. A color is not proof of an activation.
* **Decoded from generated trace** means actual self-fed GPU token IDs, including
  PC anchors, final commits, BYTE output and partial value records. Reference
  tokens are comparison targets only. They never supply feedback to the recorder.
* **Read from neural state** means the recorder read actual fp32 recurrent S
  tensors using the existing register and RAM observers. A snapshot is shown
  only at its exact generated prefix. Nearby snapshots are never substituted,
  interpolated or propagated into missing frames.
* **Reference** remains visible on the published showcase outputs whose manifests
  say native/software reference only. A historical manifest report is labelled
  separately and does not become an in-memory neural sample.

`FreeRun.run(n)` has generated n tokens but has not fed the last generated token
back into the circuit. S therefore reflects GO and the first n-1 generated
feedback tokens. This boundary is part of every snapshot's description. The
retained final neural PC is `0x00040014`, the pending HALT instruction. The
software reference's post-HALT PC is `0x00040018`. RAM and every register agree
literally. The importer checks this PC boundary explicitly rather than hiding
or correcting a coordinate.

DROM and code-ROM rows `p` and `p+64` hold complementary 32-byte halves of one
two-hot read. They are not duplicate rows. ROM bytes encode predecoded compiler
records. RAM words are striped across banks, value-head slots and rows. Their
address formulas come from the original snapshot and observer code.

## Regenerate the graph on the Mac

The existing project venv, clean pinned upstream and local compiler experiments
are required. No GPU or dense model materialization is needed.

```sh
.venv/bin/python experiments/explorer/export_graph.py
```

The exporter creates an isolated prepared package under `.cache/explorer/`.
It exports the actual graph and newly generated residual ownership ledger. It
calls the stock emitter's `row()` for the unit projection weights and verifies
BF16 representability. It exports coefficient counts, extrema and L2 norms,
not dense model weights. Shared q/k projections count once per value-head entry
in head statistics; this counting scope is explicit in the data. FFN statistics
include the two input rows and output column, including their zeros. Stock
exit clears and ballast cleanup are represented separately from IR terms.
The appended full-attention layer is explicitly all-zero.

## Import an existing accepted recording on CPU

This does not run a GPU job. The named checkpoint must be an actual generated
checkpoint from the same ELF and generated trace.

```sh
.venv/bin/python experiments/explorer/record.py import \
  --inputs .cache/tiny-llm/ndot-story38-20261030 \
  --actual .cache/tiny-llm/ndot-story38-20261030-actual/main \
  --checkpoint .cache/explorer/retained/checkpoint.pt
```

The importer checks every generated token against the comparison file, the ELF
and trace bindings in the checkpoint, all decoded RAM bytes, all three register
copies, and the pending-HALT PC. It saves its checks in
`data/import-validation.json`. It never constructs a checkpoint from the
reference machine.

## New periodic fused GPU capture

The shared GPU lock was held by `tiny-qwen35-training-20261030` during both
acquisition attempts, which failed safely. At final inspection the lock had
passed to `showcase-20261030a`, with an expected duration of up to two hours. **No new GPU job was started.** The
capture implementation is present, but has not been exercised on the GPU in
this session. Intermediate neural activations for position 0 are consequently
missing from the included windows. The UI labels these gaps.

When the lock becomes available, run this command from the Mac with a fresh
label:

```sh
.venv/bin/python experiments/explorer/launch_capture.py \
  --label stories-position0-FRESH --every 32768
```

The launcher atomically runs `ssh gpu "mkdir C:\Users\Admin\gpu-lock"`. It
returns without starting work if that fails. On success it writes owner, start
time and expected duration, tar-syncs only its dependencies into a new isolated
`artifacts/explorer-LABEL/repo` directory, verifies the existing remote venv,
and detaches encoded PowerShell through `Invoke-CimMethod Win32_Process Create`.
It performs no installs and never kills another task's process. The supervisor
releases the lock in `finally`, including on capture failure, and bounds its own
worker to 15 minutes. Failed launch setup also releases the lock.

The recorder uses the accepted fused executor from boot, records generated
tokens, observes the first 8,192-token prefix and periodic S snapshots, and stops
after one full inner position. Every generated token is checked against the
independent comparison stream. Every snapshot's registers, RAM, PC, anchor and
count are compared to the corresponding independent state after consumed
feedback, including partial-record boundaries. Reference state is never injected
after boot. Selected S heatmaps and complete RAM snapshots keep the bundle small.
`--stop 8192` makes a short boot-only capture.

After `exit.json` reports exit code zero, collect the bundle using tar over
`ssh gpu` into a private local directory, then mount it:

```sh
mkdir -p .cache/explorer/capture
ssh gpu 'tar -cf - -C C:/Users/Admin/qwenputer-games-work/artifacts/explorer-LABEL bundle' \
  | tar -xf - -C .cache/explorer/capture
python3 experiments/explorer/server.py \
  --recordings .cache/explorer/capture/bundle
```

Never launch `record.py capture` directly on the shared GPU without acquiring
the specified lock. The launcher is the coordinated entry point.

## Showcase and private decoder contract

The server reads only `experiments/showcase/manifest/*.json` when those manifests
exist. It neither modifies that directory nor assumes the demo has run neurally.
The application view lists their demo names, status, output source, evidence
paths and ELF/network bindings. Current reference-only Life, MNIST, tic-tac-toe
and SHA manifests remain reference-only in the UI.

A future manifest may set `explorer_recording` to a recording JSON path relative
to `/recordings/`. A recording uses `schema: "qwenputer.recording.v1"`, generated
trace pairs, static ELF metadata and explicitly sourced snapshots. See the
included JSON files for the complete shape. A catalog uses
`schema: "qwenputer.catalog.v1"` with `recordings` entries containing `id`,
`title`, `url`, `tokens` and `snapshots`. Put different ELF bundles in separate
subdirectories so their `program.json.gz` files do not collide.

An application-specific recording may add a `decoder` object. For example:

```json
{
  "kind": "doom",
  "title": "Neural RAM framebuffer strip",
  "address": 16781312,
  "width": 320,
  "height": 10,
  "stride": 640,
  "format": "rgb565"
}
```

This is a schema example, not an asserted Doom buffer address. Supply the actual
address and geometry from the guest's own observer/manifest. Supported Doom
formats are little-endian RGB565, RGB, RGBA and indexed bytes with an explicit
`palette` array. Life, MNIST and tic-tac-toe decode explicit one-byte RAM grids.
SHA-256 reads 32 bytes at an explicit address. The decoder refuses out-of-range
RAM, unknown pixel formats or missing indexed palettes. Private recordings and
WAD-derived pixels must stay under `.cache/`, mounted with `--recordings`.
They must never be added to `data/` or git.

## Verification and screenshots

```sh
.venv/bin/python experiments/explorer/verify_data.py
```

The retained check verifies all regenerated ownership intervals and handovers,
selected units against a real dense stock-emitted layer, every token and
instruction PC in the full first-position window, and the final decoded neural
RAM/register exports. It also rejects a one-bit register-copy corruption.
`data-validation.json` records the result. These checks use the private retained
fixture named above.

For the browser checks, start the server and a separate existing Chrome headless
profile with remote debugging on port 9223. Then run:

```sh
node experiments/explorer/verify_browser.mjs
```

This uses Node's built-in WebSocket and CDP. It checks all levels against the
loaded data, searches a real RAM bank, renders an actual S heatmap, verifies
missing-frame behavior, tests a compact viewport and the reference Life view,
and saves screenshots. `browser-validation.json` records the result. No browser
package is installed. The screenshot command expects an isolated debugging
browser already running and does not attach to the user's normal Chrome profile.

Screenshots are in `screenshots/01-network.png` through
`screenshots/08-life-reference.png`. In particular, `02-ram-bank.png` shows an
actual recurrent-state slice, `04-neural-cpu.png` shows decoded registers,
`05-inner-transformer.png` shows the inner KV inspector, and `07-story-output.png`
shows the generated story.

## Remaining gaps

* New periodic fused capture awaits the GPU lock. The included final neural
  checkpoint is real; the boot and position-0 windows currently have trace data
  only. No per-layer activation history is claimed.
* Exact dynamic call stacks, instruction-retirement profiling, and an automatic
  link from arbitrary guest addresses to an inner-model token are not implemented.
* Unclassified compiler prefixes retain exact symbols rather than guessed roles.
* Published Doom evidence has no locally loaded pixel bundle here. Doom strips
  require a private decoder recording. New showcase neural recordings load when
  their manifests supply compatible recording paths.
* The complete stock-capacity map trades orbit responsiveness for every padded
  zero unit. Use the default active map or role/layer filters for interaction.

The design uses the Model the Domain principle to keep graph structure,
generated traces and exact neural observations separate. Prove It Works shaped
the dense-emitter, generated-PC and real browser checks. Work ran inline without
nested delegation or an independent agent review, as requested.

The interaction takes inspiration from the MIT-licensed
[neuron-explorer](https://github.com/lyramakesmusic/neuron-explorer).
No upstream explorer code or assets were copied. This implementation uses the
repository's MIT license.
