# Stock Qwen3.5 CUDA execution evidence

The first complete Weight Paddle CHIP-8 framebuffer was generated by stock Transformers `Qwen3_5ForCausalLM` on an RTX 5070 Ti. All 5,415 autoregressively generated RISC-V trace tokens exactly match the pinned upstream reference. The generated frame also matches the first frame of the independently verified Mac compact execution.

The model has 2,113,019,200 parameters, constructed from compiled RISC-V circuit weights. This is the stock Qwen3.5 class with standalone compiled CPU weights. It does not contain pretrained Qwen language-model weights. The circuit uses the unmodified pinned upstream 32 KB memory map. It does not contain the later 64 KB prototype.

These are correctness runs, not a controlled performance comparison. The timed regions exclude model compilation and reference generation. The first-frame run includes PAD prefill, cache state injection, stock greedy generation, online token comparison, progress output, and checkpoint writing. `report.annotated.json` corrects the shorter original timing description and adds the derived frame count and hash. The original `report.json` is preserved unchanged.

The environment used Python 3.14.2, torch 2.14.1+cu130, CUDA runtime 13.0, Transformers 5.21.0, NVIDIA driver 617.42, and upstream commit `ca13310e2f9f788d1dd3feeea8213c1b0c23913c`. Official cu130 Windows wheels did not provide torch 2.15.0. Torch 2.14.1 satisfies the pinned upstream requirement. The full resolved package list is preserved in `requirements-cuda.txt`.

The probe asserts that both inputs and outputs are CUDA tensors and checks an exact bf16 matrix product. Stock model execution used bf16 parameters, upstream `exact_matmuls()`, `allow_bf16_reduced_precision_reduction=False`, and `allow_tf32=False`. No modules were replaced with compact or sparse executors. Stock Transformers reported reference PyTorch fallbacks for causal convolution and gated delta rule because optimized optional kernels were absent. There was no Triton installation. First-frame PyTorch peak allocated CUDA memory was 4,361,678,848 bytes. The 92 one-second GPU samples include compilation and show peak utilization of 75 percent.

`source/hf_cuda.py`, `source/hf_cuda_monitored.py`, and `source/gpu_probe.py` are the exact executed harnesses. From the repository root on Windows, run `powershell -File experiments/cuda/run-commands.ps1` or execute its commands individually. The command file copies these scripts into `tools/` so their original repository-relative imports remain intact, and uses the committed ELF under `artifacts/compact-game`. Review the commands before using an existing environment. This uses native Windows CUDA and Git installed at its standard location. It does not require WSL or Ollama.

The monitored run uses a 300-second generation deadline and a 5,415-token bound, with a checkpoint every 64 tokens. It compares actual emitted tokens online without feeding reference tokens to the model. A deadline can produce a partial report; only `completed_target: true` establishes the requested token count. The archived full run completed.

The repository artifacts include the actual generated token list, uint32 trace, raw frame output, decoded frame JSON, rendered PNG, original reports, GPU samples, and an independent local validation report in this experiment directory. The local validation rebuilt the reference from the retrieved ELF, compared every retrieved token, decoded the frame from those tokens, and compared its pixels with the Mac compact frame. No generation or sampling processes remain running. The dedicated environment and pinned upstream clone remain available for reuse.
